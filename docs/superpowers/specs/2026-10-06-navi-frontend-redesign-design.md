## 1. 背景与目标

现有前端是功能验证形态：组件可用但无设计体系，视觉与交互未达到产品承诺的「可信、高级」标准。
本次为**全量重设计**：

- 不复用任何现有页面组件，按本规格全部重写；旧组件及其测试删除。
- 保留 `apps/web/src/lib/api.ts`（HTTP 客户端与类型契约）——逻辑正确且与 UI 无关。
- 不改动 `packages/core` 推荐算法、知识库内容与 `apps/api` 既有接口契约；接口层仅有两处增量新增（见 §8.2、§8.4）。
- 目标观感：**编辑感（editorial）升学指南**——暖纸底色、墨色排印、暖橙为唯一强调色；高级感来自排印与留白，而非装饰。

## 3. 设计系统

### 3.1 色板（Tailwind 主题令牌）

| 令牌 | 值 | 用途 |
|---|---|---|
| `paper` | `#F7F3EC` | 页面底色（暖纸） |
| `surface` | `#FFFDF9` | 面板/卡片底 |
| `ink` | `#201A14` | 主文字 |
| `ink-2` | `#6E6459` | 次要文字 |
| `ink-3` | `#A39888` | 弱化文字、装饰 |
| `line` | `#E6DDD0` | 细线、描边（1px，暖灰） |
| `accent` | `#E05A1F` | 唯一强调色（暖橙）：主按钮、链接悬停、当前态、数据高亮 |
| `accent-soft` | `#FBEADF` | 橙色浅底（选中晕染、悬停底） |
| `accent-deep` | `#93380F` | 橙色文字态（链接、芯片文字） |
| `warn` | `#B07C1F` | 待核实角标、误区芯片 |
| `bad` / `bad-soft` | `#B23B2E` / `#F7E9E5` | 错误与风险语义 |
| `ok-soft` / `ok` | `#EAEFE8` / `#4A7C59` | 行动指南芯片（低饱和绿） |

规则：

- 全站只有 `accent` 一个强调色；语义色（warn/bad/ok）低饱和、只出现在对应语义处。
- 分区以**留白 + 1px 暖细线**为主；默认无卡片。面板（surface 底 + line 描边 + 14px 圆角）只用于「块本身即交互或需要边界」的内容：主推荐卡、路径详情各知识块、历史行容器、输入区。

### 3.2 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 标题 / 品牌 / 大题面 | Noto Serif SC（900/600），回退 `Songti SC`、`SimSun`、serif | 编辑感核心；自托管 woff2 子集，加载失败时回退本地宋体，不阻塞渲染 |
| 正文 | 系统黑体栈：`PingFang SC`、`HarmonyOS Sans SC`、`Microsoft YaHei`、sans-serif | 正文 16px，行高 1.9 |
| 数字 | Fraunces（500/600），回退 Noto Serif SC | 匹配分、亲和度、进度数字、日期；`tabular-nums` |

字号阶梯（偏大取向）：页面主标题 34–42px；节标题 18–19px/900；正文 15–16px；辅助 13px。

### 3.3 质感与版式

- 纸纹：3% 透明度噪点纹理叠加于 `paper` 底（CSS 生成，不用图片资源）。
- 节标题模式：`编号（橙色 Fraunces）+ 宋体标题 + 1px 细线`。**编号区右侧的设计期注记只存在于本规格与样张，实现中不渲染。**
- 内容栏最大宽度 720–780px 居中；页头（顶栏）全宽、底部 1px 细线。

### 3.4 动效原则（全部 CSS 实现，不引入动效库）

1. **级联入场**：页面内容分节以 60ms 间隔淡入 + 8px 上浮（200–240ms，ease-out）。
2. **路由过渡**：切换路由时新页面整体 200ms 淡入 + 8px 上浮。
3. **图表描画**：雷达图首次出现时 600ms 描画动画（Recharts 内置动画）。
4. **滚动显现**：结果页长内容各节滚动进入视口时一次性显现（IntersectionObserver），不重复播放。
5. **悬停抬升**：可点击行/卡片悬停时 1px 上浮 + 描边转橙；按钮悬停加深。
6. 尊重 `prefers-reduced-motion`：全部动画可关闭。

### 3.5 基础组件规格

| 组件 | 规格 |
|---|---|
| 主按钮 | `accent` 底白字，8px 圆角，15px 字；悬停加深；加载态内置 spinner 并禁用 |
| 次按钮 | 透明底、`accent-deep` 字、橙色浅描边 |
| 输入框 | `paper` 底、`line` 描边、8px 圆角、15px 字；聚焦橙色描边 + 3px 橙色浅晕 |
| 问卷选项 | **逐行竖排**，一行一个；左对齐横排文字；未选为细线描边行，选中为橙色浅晕底 + 橙描边 |
| 待核实角标 | 暖米底 + 琥珀字 + 细描边圆角标签，文案「待核实」 |
| 顶栏 | 左侧品牌 `Navi`（宋体）+ 副题「大学生生涯规划」；右侧：历史入口、账号菜单（账号名 + 登出，无其他项）；未登录显示「登录」 |

### 3.6 内容状态角标规则

- 知识库条目 `status` 为 `draft` / `review` → 显示「待核实」角标。
- `status` 为 `verified` → **不显示任何角标**（已核实是常态，不做正向展示）。

## 4. 信息架构与路由

### 4.1 路由表（wouter）

| 路由 | 页面 | 登录要求 |
|---|---|---|
| `/` | 首页：品牌主张 + 测测自己 / 测测别人 | 无 |
| `/auth` | 登录 / 注册（同页切换） | 无 |
| `/grade` | 年级选择 | 无 |
| `/quiz` | 问卷 | 无（「测测自己」在提交前要求登录） |
| `/result` | 结果页 | 无 |
| `/path/:pathId` | 路径详情 | 无 |
| `/paths` | 路径总览：七条路径入口 + 通用知识（误区、对比） | 无 |
| `/history` | 历史列表 | 需要（未登录引导至 `/auth`） |
| `/history/:recordId` | 历史详情（复用结果页视图） | 需要 |

浏览器标签页标题随页面更新；路径详情页标题为「{路径名}-详情」。

### 4.2 导航规则

- **状态守卫**：答题数据与结果只存内存（主文档 §5.5 答案不落盘）。直接访问 `/quiz`、`/result` 而无上下文时重定向回 `/`。
- **刷新行为**：`/result` 刷新后状态丢失，回首页重新测评；不做恢复。
- **登录门槛**：浏览（首页、路径详情、路径总览）免登录；**两种模式的提交都需要登录**（后端 `/api/diagnose` 要求会话，现状保持）。点任一入口时未登录则先经 `/auth`；问卷答满后若会话失效，引导至 `/auth`，登录成功后回到提交流程继续，不重新答题。
- **返回**：路径详情页提供明确的「← 回到结果」链接，不依赖浏览器回退；路径总览页不依赖来源上下文，直接进入，页内不需要返回链（顶栏品牌可回首页）。

### 4.3 选型

- **wouter**（约 2KB、零依赖）为路由库。不引入 react-router。
- 生产部署需 SPA fallback 配置（history API）；vite dev 默认满足。

## 5. 页面设计

### 5.1 首页 `/`

- 首屏即海报：品牌 + 大字标题「先看清自己，再看清**路**。」（「路」字橙色点睛）+ 副文案：
  「回答一组问题，得到你的生涯倾向，讲清路径的信息，并向Navi提问。」
- 双入口按钮：测测自己（主）/ 测测别人（次）。
- 元信息一行，仅「约5分钟」。
- 「它怎么运作」三段，编号行（非卡片），用户视角文案：
  - 01 回答一组问题——按你的年级取题，五题一组，跟着自己的感觉答就好
  - 02 得到你的倾向——根据你的回答，算出你的生涯倾向，看看七条路径里哪条更适合你
  - 03 看清路的真相——你想听和不想听的，都摆在你面前
- 「我们的承诺」三行（用户视角）：
  - 提供参考：为你提供大学路径真相和参考，你的路由你来选择。
  - 如实相告：没有数据支撑的数字，一个都不写给你看。
  - 放平心态：路径没有高低，只有适不适合你。
- 页尾一行引导（不登录也能读的浏览入口）：「也可以先随便看看——七条路径的真相与对比，不登录也能读。」其中「七条路径的真相与对比」为橙色链接，指向 `/paths`（§5.8）。

### 5.2 登录 / 注册 `/auth`

- 窄栏居中；登录 / 注册同页切换。
- 字段：**账号** + 密码（契约 `{username, password}`；禁止出现「邮箱」字样）。
- 错误内联提示于字段下方；503 时显示「账号功能暂不可用」面板（§7.3）。

### 5.3 年级选择 `/grade`

- 逐行单选，一行一个年级；选中态橙色浅晕底 + 橙描边；选定后进入问卷。

### 5.4 问卷 `/quiz`

- 进度呈现：Fraunces 数字（如 `09 / 24`）+ 2px 细进度条。
- 题面宋体半粗；选项逐行竖排（§3.5）。
- 五题一组：上一组 / 下一组；本组未答满不能前进；可回改。

### 5.5 结果页 `/result`（单栏叙事四段）

**01 你的画像**
- 左侧七维雷达图（Recharts RadarChart）：维度为 7 个画像类指标（学术志趣、积累行动力、学科认同、深造成本承受力、公共事务倾向、风险偏好、抗压续航）；**3 个意愿类指标不入图**（主文档 §9.2）。
- 右侧人设叙事：主原型名（宋体大字）+ 亲和度（Fraunces 大字 + %）+ 一句话人设（oneLiner）+ 优势/盲点两列 + 次要倾向一行（次原型名 + 亲和度）。

**02 主推荐路径**
- 唯一主推荐卡（橙色浅描边面板）：路径标题（宋体）+ 待核实角标（按 §3.6）+ 一句话摘要（summary）+ 匹配分（Fraunces 大字）+ 「查看完整真相 →」按钮，进入 `/path/:pathId`。
- 其余路径为列表行：名称 + 待核实角标（按 §3.6，与路径出现在何处无关）+ 灰色匹配条 + 匹配分 + `›`，**可点击**进入各自路径详情；悬停名称转深、`›` 转橙。
- 同分并列时按主文档规则处理为次推荐；不适用路径置灰并给出原因（主文档 §7.4）。
- **置信度（confidence）永不展示**（主文档 §7.4）。

**03 你和这条路（画像对比，主文档 §9.4）**
- 雷达叠加：学生实际值（橙色实形）与主推荐路径理想画像（墨色虚线）同图。
- 差距榜：差距最大的 **3 个**维度，每行 = 维度名 + 「你 X · 理想 Y」+ 条形图（橙条 = 你，墨线刻度 = 理想值）。
- 文案建设性口吻（「值得提前补课」），不制造焦虑。

**04 个性化解读**
- 流式输出解读文本（橙色光标）；解读下方展示**建议问题芯片，由 LLM 随解读一并生成**（见 §8.2）。
- 提问输入行 + 发送；账号级连续对话（账号文档）。
- 服务端不可用（503）时整区隐藏（§7.3）。

### 5.6 路径详情 `/path/:pathId`

- 页头：「← 回到结果」+ 路径标题（宋体 34px）+ 待核实角标 + 匹配分（从结果上下文带来；直接进入时无匹配分）。
- 摘要段落后，**知识块按知识库内顺序**逐块渲染（§6）。

### 5.7 历史 `/history` 与 `/history/:recordId`

- 列表行：Fraunces 日期（日大字 + 年月小字）+ 主推荐标题 + 元信息（测测自己/测测别人 · 年级 · 画像名）+ 匹配分 + `›`；点击进入详情。
- 详情页复用结果页视图（数据来自记录快照）。
- 空态：「还没有记录——做一次测评」。

### 5.8 路径总览 `/paths`

不做诊断直接浏览知识库的入口（主文档 §9.1「知识库支持两条访问路径……或不做诊断直接浏览」）。免登录；数据一次取齐（§8.4）。

- 页头：标题「七条路径」+ 一句说明：不需要先测评，先看清每条路要付出什么、会在哪里卡住。
- **01 选一条路，看它的真相**：七条路径行，复用结果页「其他路径」行的同一组件（`PathRow`，§5.5 02 段）。
  - 浏览态**没有测评上下文**，因此**不渲染匹配条与匹配分**——不拿 0 分或空条充数（§5.1「没有数据支撑的数字，一个都不写给你看」）。行 = 路径名 + 待核实角标（按 §3.6）+ `›`，整行可点击进入 `/path/:pathId`。
  - 结果页传匹配分与适用性时外观与现状完全一致（含不适用行置灰与原因）。
- **02 大一新生常见误区**：`common.md` 中 `myth` 类型的块，逐个按 §6 的误区面板渲染。
- **03 七条路径横向对比**：`common` 中其余块（差异对比表、风险对比表），按 §6 的对比芯片 + 表格排版渲染。
  - 取「其余」而非类型白名单：将来知识库在 `common.md` 里用了新块类型，它们仍在本页渲染而不是被丢掉（硬性约束 3）。
- 两节各自保持知识库内顺序；分节按类型归组（误区 / 其余），不做跨类型的交叉重排。
- 本页**不含**个人画像、匹配分、解读追问——凡需要测评数据的内容都不上这一页。
- 加载态骨架屏、错误态内联 + 重试（§7.1 / §7.2）。

## 6. 知识块渲染（BlockRenderer）

- 输入：知识块数组——路径详情用路径知识块，路径总览页用通用知识块（`common.md` 的 `myth` / `compare`），两者同构（知识库编译器产物，含预渲染 `html`）。块内 HTML 为**可信内容**（自有编译器产出），以 `dangerouslySetInnerHTML` 渲染，用作用域 CSS 统一排版 `p / ul / li / strong` 等元素；不引入 sanitizer 依赖。
- 每种块类型 = 中性面板（surface 底 + line 描边 + 12px 圆角）+ 头部（语义芯片 + 宋体块标题，标题取 `block.title`）+ 内容区。芯片语义色：

| 块类型 | 芯片 | 内容样式 |
|---|---|---|
| timeline 时间线 | 中性（米底灰字） | 竖向时间轴 + 节点；**「现在」标记**：解析各条目 `<strong>` 前缀的年级词，匹配用户当前年级的首条高亮（橙节点 + 「现在」标签），无匹配则不显示标记 |
| guide 行动指南 | 低饱和绿 | 「时段 / 行动」两栏行（`<strong>` 为时段列） |
| myth 误区 | 琥珀（warn） | 标题即误区名，正文即纠正 |
| cost 代价 | 墨色 | 减号「－」列表 |
| risk 风险 | 砖红（bad） | 三角「△」列表 |
| compare 对比 | 中性 | 表格样式 |
| boundary 诚实边界 | 中性 | 低调段落块 |
| free / 未识别类型 | 中性 | **降级为富文本排版**，页面不崩（硬性约束 3） |

## 7. 错误与边界状态

总原则：**降级优先于报错；结构化结果（算法产出）任何情况下完整展示。**

### 7.1 加载态

- 诊断提交：按钮内 spinner + 「正在计算……」，禁用防重复提交。
- 列表类（历史、路径总览）：暖纸色骨架屏，不用冷灰。
- 解读流式：橙色光标。

### 7.2 错误态

- 一律**内联**，不弹框；文案说明发生了什么 + 下一步（重试 / 重输）。
- 流式中断：保留已输出内容 + 「继续生成解读」芯片，不清空。
- 历史详情加载失败：内联错误 + 返回历史列表。

### 7.3 503 降级

| 场景 | 行为 |
|---|---|
| 缺 `DEEPSEEK_API_KEY`（解读/追问 503） | 结果页**整区隐藏「个性化解读」**；画像、推荐、对比、路径详情完整可用 |
| 缺 `JWT_SECRET`（账号端点 503） | `/auth` 与 `/history` 显示「账号功能暂不可用」面板；诊断提交同样不可用（`/api/diagnose` 要求会话），服务端错误文案在问卷页内联原样显示 |

### 7.4 无主推荐

全部路径不适用时不硬凑推荐：标题「这一次，没有足够适配的路径」+ 说明 + 两个出口（查看全部路径 / 重新测评）。

## 8. 技术决策与复用边界

### 8.1 依赖

| 决策 | 内容 |
|---|---|
| 新增 | `wouter`（路由）、`recharts`（图表，主文档钦定） |
| 不引入 | 组件库、动效库（framer-motion 等）、sanitizer、状态管理库 |
| 保留 | `api.ts`（HTTP 客户端与类型）、TailwindCSS |
| 重写 | 全部页面组件与顶栏；旧组件删除 |
| 测试 | 组件测试全部重写；延续行为契约（模式分流、必答门槛、错误透传、流式渲染、503 隐藏） |

### 8.2 建议问题字段（接口层新增之一）

解读响应中追加 `suggestions: string[]`（建议问题，由 LLM 随解读生成，0–3 条）。
该字段由 `apps/api` 解读提示词产出，属增量字段，不影响既有契约；前端缺省时不渲染芯片。

### 8.3 字体加载

Noto Serif SC 与 Fraunces 以 woff2 子集自托管于 `apps/web`（`@font-face`，`font-display: swap`）；网络失败回退本地宋体/衬线栈，不阻塞渲染。

### 8.4 通用知识端点（接口层新增之二）

新增 `GET /api/overview` → `{ paths: PathSummary[], common: Block[] }`。**免登录**（浏览不挡，主文档 §9.1）。

- `paths`：七条路径的摘要，复用既有构造（与 `/api/questions` 同源）——只含 `id / title / category / span / status / summary`，**不含知识块与权重**。
- `common`：知识库编译产物 `bundle.common` 原样下发（`myth` / `compare` 块，见主文档 §6.1）。
- 为什么单开一个页面级端点：`/api/questions` 的语义是「按年级取题」，拿它取一份与题目无关的路径清单语义别扭；`/api/meta` 是画像与指标定义，且前端用模块级 promise 令其全应用只取一次，塞入通用知识正文会让每次启动都多拉一份。此端点与 `/api/assessments/:id` 自带 `paths` 同属「页面一次取齐」的既有模式。

## 9. 与主文档的差异（评审通过后回写）

| # | 主文档原设计 | 本规格修订 | 理由 |
|---|---|---|---|
| 1 | §9.7 雷达图移动端降级（条形图回退） | 顺延，本轮只做桌面端 | 用户确认范围裁剪 |
| 2 | §9.3 其他路径只读 | 其他路径可点击进入各自详情 | 详情页建成后无额外成本，用户决策 |
| 3 | §9.2 画像卡布局（未限定） | 单栏叙事流：画像 → 推荐 → 对比 → 解读 | 方案 A，用户选定 |
| 4 | 未规定路由 | wouter 轻量路由 | 用户决策（为二期分享链接铺路） |
| 5 | §9.1 知识库浏览入口（不做诊断直接浏览） | 本轮实现：新增 `/paths` 总览页（§5.8），复用路径行组件与通用知识块渲染 | 用户决策，关闭原顺延项 |

## 10. 验收要点

1. `pnpm build` / `pnpm lint` / `pnpm test` 全绿；知识库编译 0 告警。
2. 同一学生重复测评结果一致（推荐逻辑未动，回归黄金案例集通过）。
3. 全站无「邮箱」字样；无置信度展示；`verified` 内容无角标。
4. 未识别块类型、缺 API Key、缺 JWT_SECRET 三种降级路径手动验证通过。
5. 桌面端（≥1024px）各页面与样张一致；`prefers-reduced-motion` 下无动画。
6. `/paths` 免登录可访问；浏览态路径行**不出现匹配条、匹配分或空条**（不编造数字）；七条路径与 `common.md` 全部通用块均在页面呈现。
7. 抽出 `PathRow` 后，结果页「其他路径」行的外观与行为与抽出前一致（既有 `ResultBody` 测试保持绿）。
