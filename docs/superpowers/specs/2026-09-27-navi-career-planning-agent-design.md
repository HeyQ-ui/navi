## 1. 项目概述

### 1.1 问题背景

大学生生涯规划存在三个结构性问题：

1. **迷茫**——学生不知道有哪些路可走，也不清楚每条路意味着什么。
2. **信息差**——各条生涯路径的真实规则、时间线、隐形门槛分散在学校官网、学长经验、招聘公告中，缺乏系统整理，且质量参差不齐。学生获取到的信息常常过时、片面或错误。
3. **时间窗口的刚性**——大学路径选择具有强时间窗口性：保研看前五学期绩点、夏令营在大三下、秋招在大四上、考公有应届生身份限制。错过窗口的决策成本极高，而学生对窗口的认知往往来得太晚。

### 1.2 产品目标

构建一个生涯规划 Agent，达成以下目标：

- 让学生看清**不同目标对应哪些大学路径**，以及每条路径的完整真相（时间线、硬门槛、软门槛、常见误区、选择它的代价）。
- 基于学生的实际情况给出**个性化路径推荐**，并说明推荐理由。
- 让推荐结果**可解释、可追溯**，学生能理解「为什么推荐这条」以及「我差在哪里」。
- 帮助学生建立**日常任务与长期目标的关联**，明确不同路径下日常侧重点的差异。

### 1.3 设计原则

| 原则 | 含义 |
|---|---|
| **确定性优先** | 路径筛选与打分由确定性算法完成，不依赖大模型推理。模型输出的波动不影响推荐结果。 |
| **可解释** | 每个推荐结果都能分解到具体指标与权重，前端可展示「为什么」。 |
| **可追溯** | 知识库内容标注校对状态，学生能分辨哪些信息已经核实。 |
| **诚实边界** | 对无法可靠回答的问题（如转专业政策细节）明确拒答并给出查询指引，不编造。 |
| **体验不凌驾于准确** | 语气以温和、建设性为准则，但事实与路径特征照实陈述——不得为了不让用户失望而软化结论。减少生硬的免责话术，但不减少必要的不确定性披露。迎合换来的满意度，是以产品承诺为代价的。 |
| **优雅降级** | 大模型不可用时，核心诊断结果仍完整可用；知识库出现未知内容类型时，前端降级为富文本渲染。 |
| **内容与代码解耦** | 知识库以 Markdown/YAML 编写，内容维护者无需接触代码。 |
| **不确定性内部消化** | 测量层面的不确定性（作答是否自洽、结果是否稳定）由系统内部承担与改进，不作为阅读负担摆给用户；知识层面的未知仍必须披露（见 §7.4 与 §8.4）。 |

### 1.4 覆盖范围

**支持的路径（7 条）**

| 目标方向 | 本学科延续 | 跨学科迁移 |
|---|---|---|
| 学术深造（保研） | 本学科保研 | 跨学科保研 |
| 学术深造（考研） | 本学科考研 | 跨学科考研 |
| 市场就业 | 本学科本科就业 | 跨学科本科就业 |
| 体制内 | 考公考编 / 选调生 | — |

体制内路径不按学科跨度切分为两条路线。学科跨度的影响体现在**可选岗位范围**上（专业对口岗与三不限岗的差异），而非路径规则本身的差异，因此由岗位层面的知识描述承载。

**明确不覆盖**

- **出国留学**：资金门槛高，目标受众窄，不作为 MVP 范围。
- **转专业**：不作为推荐路径输出。各校各学院转专业政策年度变动大、院系差异显著（绩点门槛、名额、是否降级转），无法给出可靠建议。学生主动询问时，由诚实边界机制给出拒答与查询指引（见 §8.4）。但「学科认同」指标会保留，学科认同度低的学生，推荐结果会自然偏向跨学科路径。

### 1.5 项目性质与约束

- 比赛作品，由小团队分工开发，需要清晰的模块边界以支持并行工作。
- 开发周期有限，需优先打通端到端最小闭环，再打磨表现层。

## 2. 核心概念模型

### 2.1 两条正交的轴

系统不按「读研 / 就业 / 体制内」的粗分类组织路径，而是使用两条正交的轴：

- **目标方向**：学术深造 / 市场就业 / 体制内
- **学科跨度**：本学科延续 / 跨学科迁移

两条轴交叉出的才是学生真正要走的「路」。本学科保研与跨学科保研是两套不同的规则体系（前者主要竞争绩点排名，后者还需应对先修课缺口、跨考基础、导师意向），本学科就业与跨学科就业同理。

### 2.2 指标（10 项）

所有指标均为 0–100 连续量。指标衡量的是**相对位置或倾向**，而非客观事实——绝对分数（如原始绩点）在不同学校之间不可比。

| 指标 ID | 名称 | 衡量内容 |
|---|---|---|
| `academic-interest` | 学术志趣 | 对深入一门学科、从事研究的真实兴趣（不等同于成绩好） |
| `discipline-identity` | 学科认同 | 对当前专业的认同程度 |
| `cost-tolerance` | 深造成本承受力 | 家庭可支持的教育年限、能否接受延迟就业 |
| `risk-preference` | 风险偏好 | 求稳（一次上岸）与敢赌（广撒网、接受不确定性）之间的倾向 |
| `stress-endurance` | 抗压续航 | 能否承受 1–2 年高强度备考或求职的持续消耗 |
| `public-affairs-leaning` | 公共事务倾向 | 对体制内工作内容的真实适配度 |
| `accumulation-drive` | 积累行动力 | 主动积累经历、技能、产出的行动倾向 |
| `grad-intention-baoyan` | 保研意愿 | 学生自己表达的保研倾向 |
| `grad-intention-kaoyan` | 考研意愿 | 学生自己表达的考研倾向 |
| `grad-intention-none` | 不读研意愿 | 学生自己表达的「毕业即工作」倾向 |

**前 7 项是画像指标，后 3 项是意愿指标。** 两者的区别不是程度而是种类：

- **画像指标**描述学生**是什么样的人**，由多道侧面式题目测得，参与画像原型的相似度计算（§2.3）。
- **意愿指标**记录学生**想去哪**，由同一道题供给三个互斥取值（§5.3），**不参与画像原型**——「想去哪」不是画像的一部分，把它塞进原型向量会让「稳健学术型」这类标签的含义漂移。

**关于「绩点竞争力」的删除（v1.4）**：该指标原为「在本校本专业中的相对位置」。删除的原因不是它不重要，而是**它在学生使用本产品的时段内不可得**：前五学期绩点排名在大三下学期才公示，而那时学生已不在用这个软件；大一学生只能用高考位次与第一次小测的感受这类粗代理去估，误差与题目数量都不足以支撑一个 0.30–0.35 权重的分项，还给大一导致「分项缺失」的结构性缺口。**改为由意愿决定升学方向、由其余画像指标决定适配度**（见 §7.6）。

**关于「学历刚需度」**：该指标曾被考虑，但被排除。原因是它并非学生属性，而是外部事实——「目标职业的学历门槛」属于路径知识的属性。该信息改由知识库承载，供资格过滤规则使用（如「高校教职 → 博士为硬门槛」）。

> 意愿指标与「学历刚需度」是两回事：前者是学生对自己的判断（属学生属性），后者是对外部世界的陈述（属路径知识）。

### 2.3 画像原型

系统定义 6–8 个画像原型。每个原型包含：

- 一个 7 维画像指标向量（原型中心；只含 §2.2 的画像指标，不含意愿指标）
- 一段文案包：一句话人设、优势、盲点、典型困境、建议

学生与每个原型计算相似度，输出**软归属**（如「68% 稳健学术型 + 25% 务实市场型」），而非硬分类。人数本身不适合被硬分到单一类别，软归属更符合实际，也更诚实。

**原型的双重作用**：

| 机制 | 数学 | 决定 |
|---|---|---|
| 路径匹配度 | 各指标与路径理想值的接近程度，按路径权重加权 | 推荐哪几条路 |
| 画像聚类 | 指标向量与原型向量的余弦相似度 | 怎么讲故事 |

两者共用同一个指标向量，但互不依赖，可各自独立测试与调参。

## 3. 系统架构

### 3.1 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | TypeScript | 全栈统一，前后端共享类型定义 |
| 包管理 | pnpm workspace | Monorepo，清晰的工作包边界 |
| 核心逻辑 | 纯 TypeScript，零框架依赖 | 可独立单测 |
| 后端 | Hono | 轻量、TS 友好、内置静态文件托管 |
| 前端 | React + Vite + TailwindCSS | 纯 SPA，无 SSR 心智负担 |
| 图表 | Recharts | 雷达图、条形图开箱即用 |
| 路径地图 | 自绘 SVG + d3-hierarchy | 树形布局 |
| 大模型 | DeepSeek | 国内直连、成本低、API 兼容 OpenAI 格式 |
| 模型接入 | Vercel AI SDK（`ai` + `@ai-sdk/openai`） | 与框架解耦，前端 `useChat` 支持流式 |

**技术选型理由**

**不采用 SSR 框架（如 Next.js）**：本产品是工具型应用（填问卷 → 看结果 → 追问），无 SEO 需求，无首屏服务端渲染需求。SSR 框架的核心价值在此不适用，却会引入 App Router、Server Components、水合错误等持续性心智成本。图表库在 SSR 环境下普遍需要 `'use client'` 或动态导入绕过，会挤占内容打磨的时间。

**不采用 Python 后端**：规则引擎与相似度计算均为简单数学运算，Python 无技术优势。引入第二门语言意味着额外的环境配置、CI 配置，且前后端无法共享类型定义，对小团队是净负担。

**不采用 NestJS**：后端仅是「HTTP 薄层 + 调用 `core` 包」，DI、模块、装饰器体系对此逻辑量属过度设计。

### 3.3 分层原则

**「逻辑分离」通过包边界实现，而非进程边界。** `core` 是纯函数库，不依赖任何框架、不发起任何网络请求；`llm` 依赖 `core` 的类型；`api` 是编排层；`web` 只消费 HTTP 接口。

**部署形态**：开发期为前后端双进程（各自热更新，互不干扰）；生产期由 `api` 服务托管前端构建产物，形成单服务、单端口、零 CORS 的部署。两套形态共用同一份代码，差异仅在启动脚本与静态文件中间件配置。

### 3.4 HTTP 接口

| 方法 | 路径 | 说明 | 会话 |
|---|---|---|---|
| `GET` | `/api/questions?grade=&major=` | 获取问卷。服务端按年级/专业返回适配后的题目集（见 §5.4） | 公开 |
| `POST` | `/api/diagnose` | 提交答案，返回结构化诊断结果并落库，响应含 `assessmentId` | 必需 |
| `POST` | `/api/interpret` | 按 `assessmentId` 生成个性化解读（流式） | 必需 |
| `POST` | `/api/chat` | 按 `assessmentId` 追问（流式） | 必需 |
| `GET` | `/api/knowledge` | 获取路径地图数据 | 公开 |
| `GET` | `/api/knowledge/:pathId` | 获取单条路径的完整文档 | 公开 |
| `POST` | `/api/auth/register` | 注册（用户名 + 密码），下发会话 cookie | 公开 |
| `POST` | `/api/auth/login` | 登录，下发会话 cookie | 公开 |
| `POST` | `/api/auth/logout` | 登出，清 cookie | 公开 |
| `GET` | `/api/auth/me` | 当前用户 | 必需 |
| `GET` | `/api/assessments` | 本人的历次测评（只读列表） | 必需 |
| `GET` | `/api/assessments/:id` | 单次测评的完整记录，含存下来的解读 | 必需 |

`/api/diagnose` 是系统的核心接口，其响应完全由 `core` 层计算，不调用大模型。

**登录只挡「测评」，不挡「浏览」**：题库与知识库端点保持公开，因此知识库仍可独立访问、独立传播（见 §9.1）。

> 上表是 v1.2 的接口面。账号模型、存储介质、追加语义与会话绑定的完整设计见
> `2026-10-02-navi-account-storage-design.md`。

## 4. 数据流

```
学生填写问卷（全部题目必答，分组卡片式呈现）
        ↓
[core] ① 指标计算       → 10 维分数（7 画像 + 3 意愿）
        ↓
[core] ② 作答一致性计算 → 每个指标的可靠性（内部留存，不展示）
        ↓
[core] ③ 资格过滤       → 硬约束剔除 / 软约束降权
        ↓                 ← 读取 knowledge：路径前置条件
[core] ④ 匹配度打分     → 每条路径 0–100，排序
        ↓
[core] ⑤ 画像软归属     → 与原型算余弦相似度，softmax 归一
        ↓
════════ 至此为纯确定性计算：无网络请求、无模型调用 ════════
        ↓
[llm]  ⑥ 个性化解读     → 结构化结果 + 题目作答 + 算法分项 + 主推荐路径知识 → 解读文本
        ↓
[web]  ⑦ 结果呈现       → 画像卡片 / 雷达图 / 主推荐路径 + 其他路径折叠 / 路径地图 / 路径详情
        ↓
[llm]  ⑧ 追问          → 同上上下文 + 对话历史（流式）
```

### 4.1 关键设计决策

**决策一：大模型不在关键路径上。**

步骤 ①–⑤ 为纯函数计算，不依赖网络与模型。当模型 API 超时、失败或欠费时，学生仍可看到完整诊断结果——画像、分数、路径推荐、时间线全部可用，仅缺少个性化解读文字。此为优雅降级，保证演示与使用的稳定性。

**决策二：追问不走向量检索。**

知识库本身具有结构（按路径 × 主题分文件），据此采用**结构化预加载**替代向量检索：

- 单条路径的文档规模为 KB 级，可直接全文载入上下文
- 跨路径问题通过路径标签与关键词做粗筛，选出 2–3 个相关文档
- 不引入向量库、嵌入模型、数据清洗链路

该方案免除了 RAG 全套基础设施，且检索结果完全可控，不会召回无关片段干扰模型。

**决策三：匹配度与聚类是两套独立数学。**

二者共用同一指标向量，但计算互不依赖，可分别单测与调参（详见 §2.3、§7）。

### 4.2 测评记录的留存

**每次完成测评后，完整作答与全部派生量都要落库。** 留存范围是一个不可裁剪的集合：

| 字段 | 说明 |
|---|---|
| 完整作答 | 题目 id → 选项索引，逐题保存，不存摘要 |
| 匹配度与推荐结果 | 本次作答对应的完整 `DiagnosisResult`（§7.8），存快照而非只存答案待重算 |
| 作答一致性 | 每个指标一份（§7.3）。**不展示给用户，但必须留存** |
| 置信度 | 每条路径一份（§7.4）。**不展示给用户，但必须留存** |
| 个性化解读 | 生成成功后连同记录一起留存（v1.2 扩展；原文未列） |

四条约束：

1. **「测测自己」与「测测别人」都留存**，不因来源不同而区别对待。
2. **追加，不覆盖。** 同一用户多次测评各自成一条记录，历史不丢。
   注意这条说的是**测评记录之间**互不覆盖，不是「行永远不被写第二次」：记录落库时
   解读为空，生成成功后被补写一次，那是该行唯一一次更新。
3. **绑定用户名**，记录归属于用户而非浏览器会话。
4. **agent 上下文只包含请求者本人的数据，且严格按来源过滤。** 这是本条的准确表述
   ——要防的是**混用**（拿别人的画像解释你），而不是「历史一律不许碰」。两条可检查的
   规则（专项 §7）：
   - **归属**：上下文里的任何一条记录、任何一轮对话，`user_id` 都必须等于请求者。
     不是本人的一律不进去；`assessmentId` 不是本人的照旧 404
   - **来源**：`source='other'` 的测评**数据**永不进入上下文；其**对话轮次**只在用户
     当前正查看那条记录时才进入——否则在「测测别人」的页面上就没法连续追问。一旦离开，
     那些轮次立即不在上下文里

   > v1.1–v1.2 时这条的实现形式是「只由单一记录构造」，因为那时上下文里就只有那一条。
   > v1.3 起上下文绑到了用户（§8.2），单一记录不再成立，但不变量照旧。
   > **别把「多记录上下文」读成违规**——违规的是混入他人数据。

**为什么留存这些不作为结论展示的字段**：作答一致性与置信度是产品质量的一手证据——§13.2 的参数校准、§5 的出题改进都依赖真实作答的离散程度分布。把它们从用户界面上撤下，恰恰是为了让它们回到该在的位置：**供系统自己判断测试质量，而不是让用户承担不确定性。**

> **实现归属**：本节的落地（账号模型、存储介质、追加语义、会话与上下文的绑定）与账号体系强耦合，已由专项设计
> `2026-10-02-navi-account-storage-design.md` 完成。当前实现：用户名 + 密码登录，
> 记录落在 `apps/api/data/navi.db`（sqlite），追加语义由「只 INSERT」保证，
> 解读在流正常结束后补写。开发阶段以本地存储器代替云端存储，接口语义保持一致。

## 5. 问卷设计

### 5.1 出题原则

三种题型原则组合使用：

| 原则 | 做法 | 反面示例 |
|---|---|---|
| **场景式** | 给出具体情境，避免抽象提问 | 「你对学术研究有兴趣吗？」 |
| **侧面式** | 询问行为与反应，避免自我评价。此举可绕过社会赞许性偏差——学生倾向于不承认自己抗压差、不努力 | 「你的抗压能力强吗？」 |
| **程度式** | 五档程度递进，而非并列选项 | A/B/C/D 并列选项 |

### 5.2 五档评分映射

```
①  0 分      ②  25 分      ③  50 分      ④  75 分      ⑤  100 分
否定 ──────────────────────────────────────────────── 肯定
```

题目方向**统一设计为「档位越高 = 该指标越高」**，不引入反向计分，降低实现与维护复杂度。

**默认映射按选项位置取档**，因此默认题型是 5 个选项。两类例外在题目 YAML 里显式声明：

| 情形 | 写法 | 取值 |
|---|---|---|
| 一题多指标（意愿题） | `scores: [{指标: 分值}, …]` | 按 `scores` 取，选项数由题目自己定 |
| 不计分的资格判断题 | `weight: 0` | 不参与指标计算，选项数不限 |

`scores` 里**某选项不写某指标，表示这道题对该指标没有信息**——不是 0 分。这个区别是要害：0 分会被读成「学生在这个维度上表达了负向倾向」，而「无信息」会让该分项经 §7.2 的重归一化被整体剔除。意愿题的「还没想好」正是靠它表达「学生没有表态」（见 §5.3、§7.2）。

### 5.3 题目示例

**场景式 + 程度式（测 `academic-interest`）**

> 导师给你一篇 20 页的英文文献，让你一周后汇报。你的第一反应更接近哪一端？
>
> ① 头疼，先找找有没有中文解读
> ② 能读，但大概率拖到最后两天
> ③ 按部就班读完，把汇报做完就行
> ④ 有点期待，会顺便查查相关文献
> ⑤ 很兴奋，希望借这个机会深入这个方向

**侧面式（测 `stress-endurance`）**

> 连续三周高强度备考，第三周某个晚上你发现自己效率明显下降。你更可能：
>
> ① 就此松懈，之后几天都提不起劲
> ② 硬撑，但状态越来越差
> ③ 调整节奏，休息一晚再继续
> ④ 主动换方法，比如换科目、找同学互相抽查
> ⑤ 早有预留缓冲，节奏一直在掌控中

**一题多指标（测三个意愿指标）**

这一类题目不用五档位置映射，而是逐选项给出分值——它的选项是**名义的**，不是程度的：

> 毕业后的去向，你现在的想法更接近哪一种？
>
> ① 想走保研：平时把绩点和排名冲上去，争取学校的推免名额
> ② 想走考研：大三大四集中突击，考进心仪的研究生院
> ③ 不打算读研：毕业后直接就业或考公
> ④ 还没想好

```yaml
options: [...]
scores:
  - { grad-intention-baoyan: 100, grad-intention-kaoyan: 0, grad-intention-none: 0 }
  - { grad-intention-baoyan: 0, grad-intention-kaoyan: 100, grad-intention-none: 0 }
  - { grad-intention-baoyan: 0, grad-intention-kaoyan: 0, grad-intention-none: 100 }
  - {}                       # 无信息：三个指标都剔除
```

三个指标**互斥**：选中一条，只在它对应的路径上拿满分，另两条拿 0 分。「不打算读研」拿的是 `grad-intention-none` 的 100 分——它是一条正向信号（就业与考公路径），不是「没有意愿」。

**按年级分流（测 `accumulation-drive`）**

大一那道「发现一门课排在班级后半段，你会怎么做」只对大一出题（`grades: [freshman]`）：它要求作答者已经历过一次期中考试。

### 5.4 年级分流机制

部分指标在低年级缺乏可观测数据。处理方式是**题目分流**：同一指标在不同年级由不同题目测量（`grades` 字段），未声明年级的题目对所有年级通用。

**权重按年级覆盖的机制已随绩点分项一起取消（v1.4）。** 它原本只为「大一没有排名、靠代理观测估计」这一个场景存在；绩点竞争力删除后，没有任何指标还需要按年级调整路径权重，而该机制在实现中从未落地（知识库 schema 里没有 `byYear`）。**留一条不生效的规则比没有这条规则更糟**——内容维护者会以为改了它有用。若将来出现同类需求，再按那时的具体指标设计。

### 5.5 答题体验

- **分组卡片式**：4–6 题一屏，每组配引导语（如「先聊聊你和现在专业的关系」），避免一次性呈现全部题目。
- **进度条与组标题**：学生可知剩余进度。
- **全部题目必答**：未完成当前分组不可进入下一组。
- **每次进入即空白**：作答只活在这一次测试里（组件内状态），**不落 localStorage**。
  每次重新进入一套测试都从零开始，中途刷新或退出不续填。

**为什么不做本地暂存（v1.4 改动）**：原设计把作答实时写进 localStorage 以便中途关闭后续填。但那个键是按**浏览器**存的，不是按**账号 + 一次测试**存的，于是：

- 换账号、换一次测评，都会读到上一次的选择——学生看到的是别人（或上一次的自己）点的选项；
- 题面改过之后（删题、换年级），暂存里的旧题目 id 会让「已完成 N / 总数」虚高、提交按钮在还有题没答时就亮起来，而提交上去的整份作答会被服务端按未知 id 拒成 400（这道防线本身是对的，它在挡被篡改的请求体）。

续填省下的那点操作抵不过这两类串味，而**推荐结果的可信度依赖作答确实是这次点的**。取舍见 §10。

## 6. 知识库设计

知识库是全系统的核心资产。设计目标：**支持内容自由生长，同时保证前端渲染稳定**。

> **核心机制：自由文档 + 稳定的块级契约 + 优雅降级。**
> 新内容可以在前端支持它之前先写入知识库，内容侧与渲染侧解耦。

### 6.1 目录结构

```
packages/knowledge/
├── indicators/            # 指标定义（各一个文件）
├── archetypes/            # 画像原型（各一个文件）
├── questions/             # 问卷题目 → 指标映射
├── common.md              # 通用知识（跨路径共用）
├── boundaries.md          # 诚实边界清单
└── paths/                 # 路径文档
    ├── same-discipline-baoyan/      # 本学科保研
    ├── cross-discipline-baoyan/     # 跨学科保研
    ├── same-discipline-kaoyan/      # 本学科考研
    ├── cross-discipline-kaoyan/     # 跨学科考研
    ├── same-discipline-job/         # 本学科本科就业
    ├── cross-discipline-job/        # 跨学科本科就业
    └── civil-service/               # 体制内（考公考编 / 选调）
```

**两类顶层通用文件。** `common.md` 与 `boundaries.md` 是仅有的跨路径内容：后者放
「我们答不了什么」（§8.4），前者放不属于任何单一路径的知识——大一新生常见误区、
多路径横向对比。两者都是 **`:::` 容器序列**（没有 `@block` 注解，块类型取自容器名），
每条容器各成一块，走 `parseContainers` 编译。

**通用内容走独立文件，不走复制。** 同一段误区复制进七条路径，改一处就要改七处，
而七份之间迟早会不一致——对一个以信息准确性为承诺的产品，这是最坏的失败形态。
跨文档 `@include` 复用机制在 MVP 内不实现（§6.5），通用内容因此落在一个文件里，
由编译产物统一供所有路径与上下文使用。

### 6.2 文件级元数据

每个路径文档的 frontmatter 保持极简且长期稳定：

```yaml
---
id: same-discipline-baoyan
title: 本学科保研
category: academic          # academic | employment | civil
span: same-discipline       # same-discipline | cross-discipline
status: verified            # draft | review | verified
updated: 2026-09
summary: >                  # 200–300 字核心摘要，供追问上下文使用
  保研的实质是……
---
```

**`status` 校对状态是产品信任机制的一部分。** 前端对 `draft` 内容显示「此部分待核实」角标。对一个以「抹平信息差」为承诺的产品，明确标注哪些信息尚未核实，比暗示全部可信更可靠。

**通用文件不带 frontmatter。** `common.md` 与 `boundaries.md` 都是纯 `:::` 容器序列，
文件级元数据没有消费者——`status` 的角标机制挂在路径文档上。通用内容要声明自己的覆盖
范围或待核实状态时，写进块的正文：模型读得到，维护者也读得到。

**题目文件的字段（`questions/*.yaml`）**

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | 是 | 全局唯一。**改题目的语义就要换 id**：复用旧 id 会让客户端 localStorage 里那条旧作答被当成新题的答案，静默串味 |
| `text` / `options` | 是 | 题干与选项 |
| `weight` | 是 | 题目权重。`0` 表示不计分（资格判断题） |
| `indicator` | 二选一 | 单指标题：各选项按五档位置映射到该指标 |
| `scores` | 二选一 | 多指标题，与 `options` 等长；某选项缺某指标 = 这道题对该指标无信息 |
| `grades` | 否 | 限定年级，不写则对所有年级通用 |

`indicator` 与 `scores` 必须有一个，不能都缺。「默认 5 个选项」的要求只对走五档映射的题成立（见 §5.2）。

### 6.3 块级契约

正文使用 Markdown，语义段落通过 `@block` 注解标记类型：

```markdown
<!-- @block type="timeline" -->
## 保研时间线

- **大三上 · 9月** 前 5 学期绩点排名公示
- **大三下 · 6-7月** 夏令营投递（黄金窗口，多数人在此阶段定局）
- **大四上 · 9月** 推免系统开放、预推免、正式推免

<!-- @block type="myth" -->
:::myth 排名前 10% 就稳了
绩点只是入场券。科研经历、英语、竞赛加分项在很多学校能直接改写排名结果。
:::

<!-- @block type="cost" -->
:::cost 选择保研，需要放弃
- 大三暑期无法参加实习（秋招的关键积累期）
- 考研备选窗口极短，10 月才决定风险很高
:::

<!-- 无匹配类型的内容直接书写，前端按富文本渲染 -->
```

**四个设计要点：**

1. **块类型开放**：新增内容类型（如 `case`、`compare`）无需修改任何 schema。
   当前在用的类型见 §6.4 的渲染映射表；内容侧用了而渲染侧还没有的类型，就是尚未实现的类型。
2. **不强制字段**：一条路径可以只有 2 个块，也可以有 20 个。内容先写，结构后长。
3. **优雅降级**：前端遇到未识别的块类型时按富文本渲染。内容侧可先于渲染组件发布内容。
4. **标记不外泄**：`@block` 注解与 `:::` 容器标记是**编写期语法**，既不得出现在渲染产物里，也不得进入模型上下文。编译时须将其剥除，只保留正文；块类型与标题转为结构字段（`type` / `title`）。

   第 4 条不是洁癖。模型一旦读到 `:::myth` / `:::cost` 这类标记，就会把块类型当作可以招募给用户的话题——「我可以告诉你时间线、一些误解和要付出的代价」这类句子正来源于此。标记泄漏会直接改变模型的行为。

### 6.4 编译与渲染

```
knowledge/*.md  ──[build.ts: marked 解析]──▶  dist/knowledge.json
                                                 ↓            ↓
                                           core 层读取    web 层渲染
```

- **构建时编译**，运行时不解析文本，零运行时开销。
- **通用内容一并编译进产物**：`common.md` 的块进入 `bundle.common`，与 `boundaries.md`
  进入 `bundle.boundaries` 同构。`llm` 层只读编译产物，不跨包去读源目录。
- **编译期校验**：`id` 唯一性、引用完整性、块类型合法性。校验失败**仅警告不阻断**——不能因内容侧使用了新的块类型而导致构建失败。

**前端渲染映射**

```
BlockRenderer
  ├─ timeline   → <Timeline />       竖向时间轴
  ├─ guide      → <GuideList />      分时段行动指南
  ├─ myth       → <MythCard />       误区卡片
  ├─ cost       → <TradeoffPanel />  「需要放弃什么」
  ├─ risk       → <RiskPanel />      风险与失败后的时间窗口
  ├─ compare    → <CompareTable />   路径横向对比
  ├─ boundary   → <BoundaryNotice /> 诚实边界提示
  └─ 未识别类型 → <RichText />        降级渲染，永不失败
```

`BlockRenderer` 与其下全部组件都尚未落地。v1.5 新增的 `guide` / `risk` / `compare` 与
既有的 `timeline` / `myth` / `cost` 处于同一状态：内容先写，前端按未识别类型降级为
富文本，落进 `<RichText />`——这正是 §6.3 第 3 条的用途，不是待修的缺口。组件补齐前，
这些内容在界面上是能读的富文本，在模型上下文里则与其它块同等使用。

- 跨文档 `@include` 内容复用
- 逐条事实的来源级追溯（MVP 以文件级 `status` 覆盖）

## 7. 核心算法层

`packages/core` 为纯逻辑层：零框架依赖、零网络请求、全部为纯函数，输入输出均为普通对象。

### 7.1 指标计算

题目得分区间为 0–100。单个指标由多道题测量，取加权平均：

```
score(indicator) = Σ(题目得分 × 题目权重) / Σ(题目权重)
```

单指标题的题目得分由选项位置取五档（§5.2）；多指标题由 `scores` 取，且**只有该选项写了这个指标，这道题才参与该指标的计算**——没写就是「无信息」，与未作答同样处理，连分母都不进。

**约束**：每个指标至少由 3 道题测量。§7.3 的作答一致性以题目得分的离散程度为依据，题目数量过少时该度量不具统计意义。

> **例外：多指标题供给的指标不受这条约束。** 一道题同时当保研意愿与考研意愿，按「3 道题」要求它是不可能满足的条件。这类指标天然只有一题，其代价见 §7.3。

**未知状态**：全部题目必答，答题校验也要求如此；但**「无信息」选项使 `unknown` 重新成为主路径的一种正常结果**——意愿题选「还没想好」时，三个意愿指标都没有数据，`known` 为 false，对应分项被 §7.2 剔除。这是设计意图，不是容错兜底。

### 7.2 权重重归一化

每条路径在知识库中定义权重向量，权重和为 1。学生已知指标集合为 `K`，未知集合为 `U`：

```
W'[i] = W[i] / Σ(k ∈ K) W[k]      当 i ∈ K
W'[i] = 0                          当 i ∈ U
```

**该机制是设计的一部分，不是兜底（v1.4）。** 意愿题选「还没想好」时，三个意愿指标一并未知、被整体剔除，结果回落到画像指标上——这就是「学生没表态就该按没表态算」的实现方式，而不是给它一个中性分。

> v1.1–v1.3 时这段话写的是「正常流程下不触发，作为鲁棒性保障存在」，因为那时全部题目必答、全部指标必然已知。v1.4 引入「无信息」选项后，重归一化成了承载产品语义的机制，那句话说反了。

### 7.3 作答一致性

置信度的来源。同一指标下的多道题应指向同一构念；若学生的回答高度离散，说明其在该维度上的自我认知不一致，据此下调置信度。

```
consistency(i) = max(0, 1 − stdev(指标 i 各题得分) / 50)
```

标准差理论最大值为 50（一半得 0 分、一半得 100 分），此时一致性为 0。

**单题指标的一致性恒为 0**：一道题算不出离散程度。三个意愿指标都是这种情况，于是它们在 §7.4 的置信度里贡献 0——四条升学路径与三条非升学路径的 `confidence` 会因此结构性偏低。这不影响任何对外呈现（§7.4 已把它隐去），但做 §13.2 的校准时要记得：**这些路径的 confidence 低不代表测量质量差，而是它依赖了一个单题分项。**

**该量对外隐去（v1.1）。** 它唯一的作用是推导置信度，以及供系统内部留存与后续校准（见 §4.2、§13.2）；既不展示给学生，也不进入模型上下文（见 §8.2）。理由见 §7.4。

### 7.4 置信度

```
confidence(path) = Σ(W'[i] × consistency(i))
```

其中 `W'` 为 §7.2 重归一化后的权重（和为 1），因此该式为一致性按路径权重的加权平均。

即：权重越高、作答越自洽的维度，对这条路径的判断越可靠。学生若在「学术志趣」上回答前后矛盾，则依赖该维度的路径置信度自动降低。

**算法保留，对外隐去（v1.1）。** 置信度不再展示、不再进入模型上下文，改为随每次测评留存入库（见 §4.2）。

设计理由：把「这次测出来可能不准」的疑问摆在用户面前，等于让用户承担了本应由系统承担的风险。**测试应当通过题目设计与算法设计去包容作答不一致与置信度误差，而不是把这两个不确定性转嫁给用户。** 学生做一次测评，就该得到一个明确的结论；质量保障是系统的内部职责，不是学生的阅读负担。

因此本条对界面与提示词的约束是：**不得出现置信度数值，也不得出现「你的回答前后不一致，所以结果可能不准」这类把责任推回用户的表述。**

> **注意区分两件事**：本节处理的是**测量不确定性**——隐去。**知识层面的未知**（转专业政策、分数线预测等系统本就没有可靠信息的问题）仍必须照实披露并给出查询途径，§8.4 的诚实边界不受本修订影响。二者的分界是：**我们没测准**（内部消化）与**我们不知道**（据实告知）。

### 7.5 资格过滤

每条路径声明前置条件，供确定性过滤。缺少此环节会产生荒谬推荐。

```yaml
eligibility:
  - id: has-tuimian-quota
    question: 你的学校是否具备推免资格？
    severity: hard
    failMessage: 你的学校没有推免资格，这条路对你当前不成立
  - id: gpa-threshold
    severity: soft
    failMessage: 你的绩点位置距保研线较远，需要显著投入追赶
```

- `hard` 失败 → 路径标记为「不适用」
- `soft` 失败 → 路径保留，匹配分打折

**`passWhen` 里写的是选项下标，不是选项文本。** 改选项的顺序或数量必须同步改它，否则条件会匹配不到任何作答：`hard` 的表现为该路径对**所有人**都不适用，且不报错——不读代码根本看不出是这里坏了。合并选项时尤其容易漏（下标会平移）。

**设计决策：「不适用」的路径不占主推荐位，但也不隐藏。**

结果页主区只呈现**一条**路径——**匹配度最高的可适用路径**（见 §9.3）。硬性不适用的路径不占主位，否则会出现「只给用户看一条他根本走不了的路」。

但它们也不被丢弃：全部路径（含不适用者）收进结果页的只读折叠区，逐条列出原因。原因本身就是有价值的信息——「你的学校没有推免资格」这句话，可能正是该学生最需要知道的事。**「不隐藏」的义务由折叠区承担，而不是由主推荐位承担。**

### 7.6 匹配度计算

朴素做法是「指标越高越好」，但这是不准确的：指标并非越高越好，而是要看是否匹配。保研需要偏稳的风险偏好，而市场就业可能更需要敢闯。

因此每个指标按**与理想值的接近程度**计算匹配度：

```
match_i = 100 − |score_i − ideal_i|
```

权重定义中包含理想值（以本学科保研为例）：

```yaml
weights:
  - { indicator: academic-interest,       weight: 0.25, ideal: 85 }
  - { indicator: grad-intention-baoyan,   weight: 0.35, ideal: 100 }
  - { indicator: discipline-identity,     weight: 0.15, ideal: 80 }
  - { indicator: cost-tolerance,          weight: 0.15, ideal: 60 }
  - { indicator: risk-preference,         weight: 0.10, ideal: 75 }   # 保研倾向求稳
```

**意愿分项靠理想值而非新算法表达方向（v1.4）。** 三个意愿指标各只有一道题、取值互斥（§5.3），路径只要声明 `ideal: 100`，前述「与理想值的接近程度」就自动实现了「尊重学生意愿」：

| 学生选了 | 该分项在本学科保研上的 match | 在本学科考研上 |
|---|---|---|
| 想走保研 | 100 | 0 |
| 想走考研 | 0 | 100 |
| 不打算读研 | 0 | 0 |
| 还没想好 | 分项被剔除，不参与 | 同左 |

「不打算读研」在两条升学路径上都是 0 分，同时在本学科就业、跨学科就业、考公考编上各拿一个满分分项——它不是「没有意愿」，而是一条指向就业的正向信号。

权重分配（合计 1.00）：

| 路径 | 意愿分项 | 权重 |
|---|---|---|
| 本学科保研 / 跨学科保研 | `grad-intention-baoyan` | 0.35 / 0.30 |
| 本学科考研 / 跨学科考研 | `grad-intention-kaoyan` | 0.25 / 0.20 |
| 本学科就业 / 跨学科就业 / 考公考编 | `grad-intention-none` | 0.25 / 0.25 / 0.20 |

> **这份权重是可调的**（§12.2 内容侧与开发并行）。它当前的取值表达的是「意愿与画像各占多少」的一种判断：升学路径的意愿权重与其原绩点分项持平，非升学路径从原有分项里让出等量权重。真实作答积累后再校准。

加权汇总：

```
match(path) = Σ(match_i × W'[i]) / Σ(W'[i])
```

**附带的可视化价值**：该模型可直接支撑「学生画像 vs 该路径理想画像」的分维度对比，学生可直观看到差距所在（见 §9.3）。

### 7.7 画像软归属

```
similarity(student, archetype) = cosine(student_vector, archetype_vector)
```

仅对**共同已知维度**计算余弦，缺失维度不参与计算但记录覆盖率。经带温度参数的 softmax 归一化为百分比：

```
affinity = softmax(similarity / τ)
```

输出形如：`68% 稳健学术型 + 25% 务实市场型`。

`τ` 控制分布的软硬程度：调大趋近均分，调小趋近硬分类。此为可调参数。

### 7.8 输出契约

`core` 的输出结构专门为「可解释」设计：

```ts
interface DiagnosisResult {
  indicators: Record<IndicatorId, {
    score: number
    known: boolean
    consistency: number                 // v1.1：仅留存与调参，不展示、不进上下文（§7.3）
    sources: QuestionId[]
  }>
  paths: Array<{
    id: PathId
    match: number                       // 0–100
    confidence: number                  // 0–1，同上（§7.4）
    eligibility: {
      applicable: boolean
      hardFailures: EligibilityFailure[]
      softWarnings: EligibilityFailure[]
    }
    contributions: Array<{              // 分项贡献，可绘制瀑布图
      indicator: IndicatorId
      match: number
      weight: number
      contribution: number
    }>
  }>
  archetypes: Array<{
    id: ArchetypeId
    affinity: number                    // 0–1
  }>
}
```

**`IndicatorId` 含三个意愿指标**（`grad-intention-baoyan` / `-kaoyan` / `-none`）。它们在 `indicators` 与 `contributions` 里与其他指标同形，唯一的特殊之处是：单题供给，且 `known: false` 表示学生选了「还没想好」（§7.1、§7.3）。

**该结构不含任何模型生成内容**——它是确定性的、可复现的、可完整单测的。大模型仅在此基础上做二次加工。

## 8. LLM 层

### 8.1 职责边界

大模型在系统中承担三项职责，不参与任何决策：

1. **个性化解读**——将结构化诊断结果转述为学生可理解的语言
2. **追问回答**——基于知识库内容回答后续问题
3. **诚实拒答**——知识库未覆盖的内容，明确说明无法回答

该边界保证推荐结果不受模型输出的随机性影响：同一学生多次测评，路径推荐与分数完全一致，仅有解读文字存在措辞差异。

**角色设定（v1.1）**

Navi 是这次测评的**测试者**，不是旁观者。测试结果是它负责的产物，因此它有义务把「这个结论怎么来的」解释清楚——依据是学生的题目作答与算法分项，而不是凭印象反推。这决定了它自信的来源：当它说「这条路径适合你」，依据必须是 `<knowledge>` 里可指认的具体条目；拿不出依据时，它应当说没有依据，而不是含糊其辞地兜一个说法。

**语气规范（v1.1，写入系统提示词）**

| 规则 | 含义 | 适用 |
|---|---|---|
| **和善、耐心、客气** | 语气平缓。学生是低年级本科生，不是被评估的对象 | 解读 + 追问 |
| **不评判人，只陈述事** | 不对学生这个人、以及他的选择下判断；对事实与路径特征照实陈述 | 解读 + 追问 |
| **结论照实说，语气温和** | 不为了不让用户失望而软化结论。如果一条路门槛很高，就直接讲清楚。举例：学生「学术志趣」很低，问「我适不适合读博」，诚实且有用的回答是「以目前情况看，直接读博把握不大，更适合先补 X」 | 解读 + 追问 |
| **禁止生硬的免责话术** | 不出现「我不编」「我不打算自己反推」这类把内部纪律说给用户听的句子——那是工程约束，不是用户需要读取的内容。需要披露信息缺口时，说「这块我们确实没有可靠依据」并给出查询途径 | 解读 + 追问 |
| **不主动引入未问及的内容** | 用户没有问到的内容不要出现，他们可能不关心；除非用户已经产生了误解，此时主动纠正 | **仅追问** |
| **禁止以招募提问的方式收尾** | 不写「我可以告诉你时间线、一些误解和要付出的代价」这类把知识库结构报成菜单的句子。而写「有什么关于测试结果的疑问或者关于这条路径的问题，都可以问我~」 | **仅追问** |

**「适用」列是这张表的读法前提。** 解读与追问的主动性不同：解读按 §8.2 本就要主动产出四段，其中「你的变化」与「接下来关注什么」都是用户没问过的；追问才是被动应答。因此后两条**只约束追问**——把它们套到解读上，会把解读削成畏缩的复读，甚至与 §8.2 的固定输出结构直接打架。读表先看适用列。

**「不跟用户唱反调」与「给积极的分析」都落在语气层，不落在结论层。** 这两条诉求的正当内核是不说教、不打压、不摆免责声明；它们不能被读成「附和学生说错的话」或「只挑好听的说」——那会直接推翻 §1.3 的体验不凌驾于准确与 §8.3 的防幻觉约束。

### 8.2 解读场景的输入构造

```
[系统提示]   角色设定、语气要求、硬约束、解释推荐理由的规则
[学生画像]   10 维分数（7 画像 + 3 意愿。意愿分项是「为什么是这条路径」的核心依据）
[诊断结果]   路径匹配度 + 分项贡献 + 资格警告
[历次自我测评] 最近 4 次（不含当次）的分数、主推荐路径与时间    ← v1.3 新增
[画像标签]   软归属结果
[题目与作答] 本次问卷每道题的题干、选项，以及学生的选择
[目标路径]   从知识库按 id 取出，全文载入（已剥除编写期标记）
[全部路径摘要] 每条路径的 summary
[此前的对话] 账号级对话流的最近数轮（已按来源过滤）            ← v1.3 新增
[输出要求]   固定结构（分段与篇幅约束）
```

**「历次自我测评」与「此前的对话」是 v1.3 新增的两块，它们让 agent 上下文绑定到用户**
（专项 `2026-10-02-navi-account-storage-design.md` §11）。在此之前上下文只有当次测评，
换一次测评就「失忆」。「历次自我测评」的标题会写明**不含本次**——模型看到一串历史时
很容易把最近那条当成当次，那会让解读的「你的变化」段算错一次。

**这两块严格按来源过滤**：`source='other'`（替别人测）的测评数据**永不进入上下文**；
其对话轮次只在用户当前正查看那条记录时才进入。这是 §4.2 第 4 条的落地，见该节。

**「题目与作答」是 v1.1 新增的核心上下文。** 没有它，模型无法回答「为什么是这条路径」——它手里只有 8 个分数和匹配度，任何「为什么」都只能是反推，而反推就是编造。有了题目与作答，模型才具备做**有据可依的解释**的条件。这同时解释了旧版为何会输出「我不打算凭那 8 个维度自己反推一个解释」——那不是模型的态度问题，是上下文不足的必然结果。

**「分项贡献」必须由 `core` 算好后传入，不得传入原始权重与原始作答让模型自行计算。** 前者是「学术志趣贡献了 21 分、学科认同拖了 9 分」这类已完成的分解；后者会让模型开始做算术并自行得出结论，直接违反 §1.3 的确定性优先——推荐结果由算法得出，模型只做转述。

**模型读到的路径正文必须是剥除标记后的纯正文**（见 §6.3 第 4 点）。`@block` 注解与 `:::` 容器标记属于编写期语法，一旦进入上下文，模型会把块类型当作可招募的话题报给用户。

单条路径文档为 KB 级，因此**全文载入，不做检索**。此举使模型输出的每句话都能追溯到知识库中的具体内容，构成防幻觉的第一道保障。

**解释推荐理由（v1.1）**

学生问「为什么这条路径适合 / 不适合我」时，模型须基于**题目、作答与分项贡献**用口语化的方式说明原因，而不是复述分数。

学生索要算法本身时，给**构成要素**而非公式：

> 「这条路径主要看你的学术志趣和积累行动力，你在这两项上的位置是……；学科认同拖了一点后腿。」

这样处理既不是回避，也无需公开公式——**说清「由哪些因素构成」已经足够，而这些因素本身就在上下文里**，是有依据的真话。

**解读的输出结构（v1.3：三段改四段）**

1. **你现在的位置**
2. **为什么推荐这条路径**
3. **你的变化**（v1.3 新增）
4. **接下来关注什么**

第三段讲这次与之前相比画像往哪个方向动、这对路径判断意味着什么。**当次之前没有自我
测评时（首次测评），这一段要照实说明这还看不出变化**，不编造一份「上次」——编造对比比
留白更糟。

**除「你的变化」段以外，不要主动做跨次对比**，其余三段按最近一次的情况讲。追问侧同理：
上下文里有多次自我测评数据、但学生没有明确提出对比时，不要主动对比（见 §8.5）。

### 8.3 防幻觉约束

写入系统提示词的硬约束：

> 「你**只能**使用 `<knowledge>` 标签内的信息。知识库未覆盖的内容，**禁止**基于常识推测或补充。若学生所问不在其中，必须回答：『这部分我们没有可靠信息』，并指出查询途径。」

第二道保障为**内容可追溯**：知识库的 `status` 状态一并传入，模型被要求在解读中标出哪些信息尚待核实。

**措辞层面的补充（v1.1）**：披露义务不变，表达方式按 §8.1 的语气规范。不写「我不编」这类内部纪律陈述，而是照实说明缺口并给出查询途径，**然后继续提供已有信息**。拒答不是终点——「这块我们没有可靠依据，但关于你问的这件事，我们手上确实有的是……」明显优于一句话把话题结束掉。

### 8.4 诚实边界机制

`knowledge/boundaries.md` 将「系统无法回答什么」也纳入知识资产：

```markdown
:::boundary topic="转专业政策"
各校各学院转专业政策每年都可能调整，且涉及绩点门槛、名额、是否降级转
等大量院系差异，我们无法给出可靠建议。
建议：查询你所在学校教务处官网，或直接咨询辅导员与直系学长学姐。
:::

:::boundary topic="院校录取分数线预测"
我们不预测任何学校任何专业的录取分数。请参考官方招生简章与往年数据。
:::
```

**将「不知道」显式化是本产品的核心设计之一。** 对生涯规划领域而言，错误的信息本身就是信息差的一种形式；一个能明确说明「此问题我答不了、请去何处查证」的系统，其可信度高于一个对所有问题都给出流畅回答的系统。

### 8.5 追问的上下文组装

追问与解读**共用同一份上下文构造**（实现上即同一个组装函数），差异只在最后一条指令。追问时上下文由九部分构成：

| 部分 | 内容 | 规模 |
|---|---|---|
| 学生画像摘要 | 10 维分数 + 画像标签 | 短 |
| **本次题目与作答** | 题干、选项、学生的选择（v1.1） | 中 |
| **算法分项贡献** | 当前路径各指标的 match / weight / contribution（v1.1） | 短 |
| **当前路径全文** | 学生正在浏览的路径文档（已剥除标记） | 主要上下文 |
| **历次自我测评** | 最近 4 次（不含当次）的摘要（v1.3） | 短 |
| **最近 N 轮对话** | 维持指代关系（v1.3：账号级，非单条路径） | 中 |
| **所有路径的核心摘要** | 每条路径 200–300 字的 `summary` 字段 | 约 2K 字 |
| **通用知识** | `common.md`：大一新生常见误区、多路径差异与风险对比（v1.5） | 短 |
| **诚实边界清单** | `boundaries.md`：我们答不了的问题及查询途径（§8.4） | 极短 |

**「最近 N 轮对话」在 v1.3 变成了账号级的一条连续流**（专项 §11.3）：换路径、换测评、
下次登录都接着上文，不再锚在「记录 × 路径」上。历史由**服务端持有**——客户端只发本轮
问题，请求体里的历史一概不看，与 `assessmentId` 同理。

**来源过滤**：`source='other'` 的测评数据永不进上下文；其对话轮次只在用户当前正查看那条
记录时才进（§4.2 第 4 条）。

「所有路径摘要」用于回答跨路径对比类问题（如「保研和考研该如何选择」）。载入摘要而非全文，使 token 规模保持可控。

**「通用知识」接的是同一类问题**（v1.5）。摘要是「每条路各是什么」，通用知识里的对比表
是「它们差在哪、各自会栽在哪」。只有摘要时，跨路径的差异只能由模型现场归纳，而这类差异
恰恰是知识库该给出的事实——**归纳出的差异不受 §8.3 的可追溯约束**，与编造只有一线之隔。

注意：结果页收敛为单一主推荐路径（§9.3）之后，这类跨路径问题失去了界面入口，但**摘要仍保留在上下文中**——用户完全可以口头问出「那考研和保研比呢」。撤掉入口是为了降低认知负担，不是为了取消这个能力。

### 8.6 流式输出

DeepSeek 兼容 OpenAI 接口格式。后端使用 Vercel AI SDK 的 `ai` 核心包配合 `@ai-sdk/openai`（`baseURL` 指向 DeepSeek），可运行于任意 Node 服务；前端使用 `useChat` 获得流式对话体验，无需手写 SSE 解析。

### 8.7 降级策略

| 故障情形 | 表现 |
|---|---|
| 模型超时 / 失败 / 欠费 | 结构化诊断结果完整可用，仅提示「个性化解读暂不可用」 |
| 追问请求失败 | 提示重试，不影响已展示内容 |

### 8.8 提示词管理

提示词存放于 `packages/llm/prompts/*.md`，不硬编码在 TypeScript 中。理由：可 diff、可版本管理、可由非开发人员修改。

## 9. 前端与可视化

### 9.1 页面结构

```
首页 ──▶ 登录 / 注册 ──▶ 选择测评对象 ──▶ 诊断问卷 ──▶ 诊断结果页 ──▶ 追问对话
                         （测测自己 / 测测别人）           │
                                                          ├──▶ 我的历史（只读）
                                                          └──▶ 路径知识库（可独立访问）
```

**登录是「测评」的门槛，不是「浏览」的门槛**（v1.2）。题库与知识库端点保持公开
（§3.4），所以「知识库可独立访问」这条性质不受影响；分享链接的观看者也无需登录即可
看结果，只是点解读或追问时会被要求登录。

**入口分「测测自己」与「测测别人」两支**（v1.1）。两支走**完全相同**的题目、算法、
解读与追问，唯一差别是落库时的来源标记（见 §4.2）：无论如何都留存。解读讲的始终是
**被测量的那个人**，所以替别人测时，解读与追问锚在那次记录上、可以直接转给对方看。

§4.2 第 4 条要防的是**混用**（拿别人的画像解释你），而不是「不许碰别人的记录」：
只要上下文只由当前这一条规定记录构造，就没有混用。措辞以 §4.2 为准。

**「我的历史」是只读的历次测评列表**（v1.2）。点进任意一次复用结果页渲染；解读直接
读存下来的那段，不重算（见 §4.2），追问则仍是实时问答。

**追问是账号级的一条连续流（v1.3）**，不是「就这条路径追问」。对话区的位置不变（仍在
结果页主推荐路径下方，因为那是有问题要问时人在的地方），但它的口径变了：换路径、换一次
测评、下次登录，都接着上文。**解读仍然锚在路径上**——换路径时重新生成——这是两者的关键
差别，别把它们混成一件东西。

**知识库支持两条访问路径**：诊断后携带个人画像进入，或不做诊断直接浏览。后者使产品具备内容属性，知识库本身可独立传播。

**诊断结果页支持分享链接**（画像状态序列化至 URL），学生可将结果分享给家长或学长。

### 9.2 可视化组件清单

| 组件 | 作用 | 类型 |
|---|---|---|
| 画像卡片 | 人设标签、性格描述、优势、盲点 | 叙事载体 |
| 主推荐路径卡 | 唯一的推荐路径：标题、匹配度、适用性说明 | 决策载体 |
| 其他路径折叠区 | 其余路径的匹配度与不适用原因，只读、无选择功能 | 备查 |
| 7 维雷达图（画像指标） | 学生画像全貌 | 诊断载体 |
| 画像对比小窗 | 学生画像 vs 该路径理想画像 | 诊断载体 |
| 路径地图 | 全域分岔树，可交互下钻 | 知识资产显化 |
| 时间线 | `timeline` 块渲染 + 当前位置标记 | 知识资产显化 |
| 误区卡 / 代价面板 / 风险面板 | `myth` / `cost` / `risk` 块渲染 | 知识资产显化 |
| 行动指南 | `guide` 块渲染（分时段行动建议） | 知识资产显化 |
| 路径对比表 | `compare` 块渲染（通用知识，`common.md`） | 知识资产显化 |

### 9.3 主推荐路径与同分提示

**结果页只给一条主推荐路径**（v1.1）：匹配度最高的**可适用**路径。7 条路径并列的选择器被撤销——「在 7 条路里自己挑一条」对低年级学生是认知负担，而不是帮助。

```
┌──────────────────────────────────────────────┐
│  主推荐                                       │
│  本学科保研                      匹配度 78    │
│  位置与需要补的差距：……                       │
│                                              │
│  ▸ 查看其他 6 条路径（含 2 条对你暂不适用）   │  ← 只读折叠
└──────────────────────────────────────────────┘
```

三条规则：

1. **只取可适用路径。** 硬性不适用（§7.5 的 `hard` 失败）的路径不进入主位，否则会出现「只给用户看一条他根本走不了的路」。
2. **全部路径可查，但不占主位。** 其余路径收进只读折叠区，逐条列出匹配度与不适用原因，没有选择功能。§7.5「不隐藏」的义务由折叠区承担。
3. **同分才提示并列。** 若存在显示分相同（按 `Math.round(match)` 比较）的其他路径，在主区内一并列出并说明「这几条对你很接近，差异在于各自的代价与时间线，而不是谁更合适」。

   判据用**取整后的显示分**而非原始浮点值：`match` 是加权和，精确相等在实际数据里几乎不可能出现，按浮点比较会让这条提示永不触发。而用户屏幕上看到的分数一样时提示就出现——这与直觉一致，也真正可达。

   分差不为零时**不提示接近**。现有算法不足以分辨细微差距（§13.2），假装能分辨是过度承诺。

**置信度不参与任何可视化。** 匹配度不再绘制为「实心段 + 斜纹浮动区间」，界面与提示词中都不得出现置信度（§7.4）。

### 9.4 画像对比组件

用于展示「学生画像 vs 该路径理想画像」的差异。推荐形态为**雷达图叠加 + 差距榜**：

```
┌─ 你的画像 vs 本学科保研的理想画像 ──────────┐
│                                            │
│              学术志趣                       │
│                 ▲                          │
│      积累行动力 ─┼─ 学科认同                 │
│                 │                          │
│      风险偏好  ─┼─ 深造成本                 │
│                 ▼                          │
│              公共事务                       │
│                                            │
│   ━━ 实线 = 你    ┄┄ 虚线 = 理想            │
│                                            │
│  差距最大：                                 │
│   · 积累行动力   你 40 / 理想 85    −45     │
│   · 学科认同     你 45 / 理想 80    −35     │
│   · 学术志趣     你 72 / 理想 85    −13     │
└────────────────────────────────────────────┘
```

雷达图提供直觉，差距榜提供行动依据。学生不仅需要看到形状差异，还需要知道**具体差在哪、差多少**——后者正好衔接后续的解读文字。

**意愿指标不进这张图（v1.4）。** 它记录的是「想去哪」而不是「是什么样的人」，混进画像雷达会让形状失去含义（且它与路径理想值的对比是另一回事）。它在解读文字与追问里出现，作为「为什么推荐这条路径」的依据。

### 9.5 路径地图

以「学生当前专业」为起点展示分岔结构：

```
                     ┌── 本学科保研   78 ▓▓▓▓▓▓
        ┌── 学术深造 ┼── 跨学科保研   68 ▓▓▓▓
        │            ├── 本学科考研   61 ▓▓▓
你的专业 ┼            └── 跨学科考研   55 ▓▓
        │
        ├── 市场就业 ┬── 本学科就业   70 ▓▓▓▓▓
        │            └── 跨学科就业   64 ▓▓▓▓
        │
        └── 体制内   ── 考公考编/选调 52 ▓▓
```

- **节点颜色深浅 = 该学生的匹配度**，使知识结构与个人结果在同一视图中合一
- 点击节点下钻，展开该路径完整文档
- 「不适用」的路径灰显，悬停显示失败原因

该视图同时呈现三件事：有哪些路可走（抹平信息差）、自己适合哪条（个性化）、每条路的差异（任务侧重点不同）。

## 10. 边界情况

| 情况 | 处理方式 |
|---|---|
| **同一指标上作答前后矛盾** | 系统照常计算并留存一致性与置信度，但**不向用户提示**（见 §7.4）。不阻断流程。 |
| **低年级学生未经历的场景题** | 通过年级分流保证每道题对目标年级可作答（见 §5.4）。 |
| **所有路径均 hard 不适用** | 主区不出现推荐路径，改为输出「当前没有匹配的路径」，逐条解释原因并给出建议。此为有价值的信息，不是错误页面。 |
| **多条路径显示分相同** | 主区内一并列出，说明「这几条对你很接近，差异在于各自的代价与时间线」。判据是取整后的显示分（见 §9.3）。分差不为零时不提示接近。 |
| **不属于任何画像原型** | 取最接近的一个，并标注「你的画像比较独特」。 |
| **学生在意愿题上选「还没想好」** | 三个意愿指标一并 `known: false`，分项经重归一化整体剔除，结果由画像指标决定（见 §7.2）。**不当作缺答、不阻断提交、不给中性分。** |
| **问卷中途刷新或退出** | 作答不做持久化，返回即从空白开始（见 §5.5 的取舍说明）。 |
| **换账号 / 再测一次** | 同样是空白开始：作答不落任何跨会话的存储，不存在读到上一次选择的情况。 |
| **某条路径内容尚未撰写** | 显示「此路径内容建设中」，不做空白或报错处理。 |
| **知识库存在未识别块类型** | 前端降级为富文本渲染（见 §6.3）。 |
| **模型服务不可用** | 结构化诊断结果完整可用，仅缺少解读文字（见 §8.7）。 |

## 11. 测试策略

### 11.1 `packages/core` 单元测试

使用 Vitest。该包为纯函数、确定性逻辑，是测试收益最高的部分：

- 多指标题的分值取值、「无信息」选项与越界下标（§7.1）
- 权重重归一化的数学正确性（含全未知、部分未知边界）
- 匹配度计算边界（理想值全中 / 全偏）
- 作答一致性的退化情况（全同分、极端分散）
- 资格过滤的 hard / soft 分支
- 余弦相似度的退化情况（零向量、维度缺失）

目标为高覆盖率。核心论点是：**推荐逻辑由确定性算法完成，大模型仅负责表达。**

### 11.2 `packages/knowledge` 校验测试

验证全部文档可解析、`id` 唯一、交叉引用完整。校验失败仅警告不阻断，与 §6.4 的降级策略一致。

### 11.3 端到端：黄金案例集

维护 3–5 个典型学生档案及其期望推荐路径，作为回归测试。

该案例集的附加价值：**同时充当内容校对工具**。知识库修改或权重调参后，运行案例集可观察典型学生的推荐结果是否发生异常漂移，防止内容改动引发意外后果。

两条纪律：

1. **答案里的题目 id 必须指向真实存在的题目**，由一条独立用例盯着。删题后不更新案例，其余用例不会报错——旧 id 只是被当成未作答，案例会静默变弱（这正是 2026-10-03 删绩点题时发现的形态）。
2. **期望的首选路径漂移时先解释成因，再改期望值。** 整体重录期望等于把回归测试变成「记录当前行为」的镜子，它就不再挡任何东西了。

## 12. 实施顺序与分工

### 12.1 实施顺序

```
1. 知识库骨架 + 编译脚本        ← 内容侧可立即开工，不被代码阻塞
2. core：指标计算 + 权重重归一化
3. core：匹配度 + 画像软归属
4. 最小前端：问卷 + 纯文本结果   ← 先打通端到端闭环，界面刻意从简
5. 接入 LLM 解读与追问
6. 可视化打磨（雷达图 / 路径地图 / 画像对比）
7. 黄金案例集 + 参数调优
```

**第 4 步刻意从简**：先确认「问卷 → 指标 → 路径推荐」链路正确，再投入时间打磨表现层。反向推进（先做界面）是此类项目最常见的时间损耗来源。

### 12.2 分工

知识库与代码解耦，使得内容工作可以完全并行：

| 角色 | 负责内容 | 前置依赖 |
|---|---|---|
| 内容 | `knowledge/` 下全部文档撰写与校对 | 无，可立即开始 |
| 算法 / 后端 | `core`、`llm`、`api` | 指标定义确定后 |
| 前端 | `web` 与可视化组件 | 输出契约（§7.8）确定后 |
| 全员 | 黄金案例审阅、路径知识交叉校对 | 内容初稿完成后 |

内容维护者无需具备编程能力。

## 13. 待验证项

以下设计基于推理，尚未经过验证。需在 MVP 完成后通过实测确认或调整。

### 13.1 跨路径追问的上下文组织方案

§8.5 提出的上下文组装策略（画像摘要 + 题目与作答 + 算法分项 + 当前路径全文 + 对话历史 + 所有路径摘要）**尚未验证**。待验证的具体问题：

- 「所有路径摘要」是否足以支撑「保研与考研如何选择」这类跨路径对比问题
- 2K 字摘要的规模是否合适，是否会导致模型忽略其中的细节
- 学生提问超出全部路径范围时，降级路径是否可接受
- **v1.1 新增的题目与作答、算法分项是否真的提升了「为什么是这条路径」这类回答的质量**——这是本次上下文补全的核心假设，需要真实模型实测来判定，不能靠推理确认
- 上下文规模增长后，模型是否仍能抓住当前路径的正文细节，而非被题目与分项稀释注意力

验证方式：MVP 完成后，构造跨路径提问样本集实测回答质量。若摘要策略不足，需评估是扩充上下文还是引入轻量检索。

### 13.2 作答一致性公式的参数校准

§7.3 定义 `consistency(i) = max(0, 1 − stdev / 50)`，其中分母 50 取自标准差的理论最大值。该取值**尚未经过验证**：

- 实际作答中题目得分的标准差通常远低于理论最大值，可能导致一致性普遍偏高，失去区分度
- 该参数的合理取值依赖真实作答数据，需在积累一定样本量后校准

验证方式：收集实际作答数据，统计各指标题目得分的标准差分布，据此调整分母或改用其他差异性度量。

**v1.1 起该量不再展示**（§7.4），但校准的必要性反而更强：它现在是纯内部质量指标，唯一的改进依据就是真实作答数据。数据来源见 §4.2 的测评记录留存。

**校准前先排除单题指标的干扰（v1.4）**：三个意愿指标各由一道题供给，其 `consistency` 恒为 0（§7.3），会把七条路径的 `confidence` 系统性压低。看 `confidence` 分布时要么按路径剔除这些分项，要么先补齐它们的题目数——否则会把「分项是单题」误读成「这批作答质量差」。

## 附录 A：术语表

| 术语 | 含义 |
|---|---|
| 路径（Path） | 一条具体的生涯路线，如「跨学科保研」 |
| 指标（Indicator） | 描述学生特征的 0–100 连续量。分画像指标与意愿指标两类（§2.2） |
| 画像指标（Profile Indicator） | 描述学生「是什么样的人」，参与画像原型相似度计算 |
| 意愿指标（Intention Indicator） | 记录学生「想去哪」（保研 / 考研 / 不读研），一道题供给三个互斥取值，不参与画像原型 |
| 无信息（No Information） | 某选项对某指标不产生分值（§5.2）。该题对该指标不参与计算，与 0 分是两回事 |
| 画像原型（Archetype） | 预定义的典型学生类型，用于软归属 |
| 匹配度（Match） | 学生对某条路径的适配程度，0–100 |
| 置信度（Confidence） | 该匹配判断的可靠性，0–1，由作答一致性推导。v1.1 起**仅供内部留存与调参**，不展示、不进模型上下文 |
| 软归属（Soft Assignment） | 以百分比表示的多原型归属，非单一硬分类 |
| 块类型（Block Type） | 知识库中语义段落的类型标记，决定前端渲染组件 |
| 硬约束 / 软约束 | 资格过滤中直接剔除路径 / 仅降权并警告的条件 |
| 诚实边界（Boundary） | 系统明确声明无法可靠回答的问题域及查询指引 |
